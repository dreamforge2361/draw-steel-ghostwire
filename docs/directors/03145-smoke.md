# 0.3.145 — Foundry checklist

A **UX hotfix, one ability.** Recompile still cannot touch a Special Sprite — that is the rule and it did not move — but it no longer tells a Technomancer they *"have no compiled sprite"* while the Special stands on the canvas in front of them.

Worlds on 0.3.144: module update + refresh (`F5`). **No pack was rebuilt**, no Actor, Item or journal page changed, and no world migration runs. Nothing to reload beyond the module itself.

**Prep.** One scene, GM client, a **Technomancer** hero with both **Compile Sprite** and **Recompile** on the Abilities tab (Sabbat Vane in the sample world has both). Have at least 1 Resonance for the reshape checks and 2 for a Special. Decompile everything first so §1 starts from an empty congregation.

---

## 1. An empty caster still reads the way it always did

This is the regression guard for the wording change: the old line is still the right line when it is true.

1. With **nothing compiled** and nothing recently destroyed, use **Recompile** (card, or right-click the row → Recompile).
2. Warning: *"Sabbat Vane has no compiled sprite to reshape and nothing recently destroyed to rebuild. Compile one first."*
3. No dialog opens, no Resonance is spent, nothing lands on the canvas.

## 2. Only a Special compiled → the real reason, not the old lie

1. **Compile Sprite** → pick **Special Sprite** from the Archetype dropdown → roll → type a purpose (*"jam the turret until we are past it"*) → it compiles. A Special Sprite token is now on the canvas.
2. Use **Recompile**.
3. → **No dialog.** The warning now names the rule:

   *"A Special Sprite cannot be Recompiled — Special Sprite (Minor) was compiled for one job and holds that shape. Compile a new Special Sprite for the new job, or compile a stock sprite (Data / Attack / Machine / Ward) if you want something Recompile can reshape."*

   The sprite's own name is in that sentence. If you still see *"has no compiled sprite"*, the fix is not live — stop and say so.
4. **Nothing is spent** and the Special on the canvas is untouched — same Stamina, same square, same purpose in its biography.
5. Compile a **second** Special and use Recompile again: both names appear in the one warning, comma-separated.

## 3. A Special standing beside stock sprites

1. Keep the Special out. **Compile Sprite** → **Attack-sprite**. You now have one Special and one stock sprite.
2. Use **Recompile** → the dialog **does** open this time.
3. The **Sprite** dropdown lists:
   - *Reshape Attack-sprite (Minor)* — selectable, and selected by default.
   - *Special Sprite (Minor) — Special Sprite, cannot be Recompiled* — **greyed out**. Clicking it does nothing; it cannot become the selection.
4. Under the form there are now **two** hint lines: the original reduced-power hint, and *"The Special Sprite rows above are greyed out on purpose: a Special is purpose-built and holds the shape it was compiled in. Compile a new Special Sprite for a new job."*
5. The **Archetype** dropdown offers **Data-sprite / Attack-sprite / Machine-sprite / Ward-sprite** and **nothing else**. Special Sprite must not be in that list.
6. Pick **Ward-sprite** → confirm. The Attack-sprite reshapes into a Ward-sprite **in the same square, at full Stamina**, and 1 Resonance is spent. The Special is not touched.

## 4. A destroyed Special is still not rebuildable — and says so

1. Decompile the stock sprite so only the Special is out.
2. Take the Special to **0 Stamina** (edit its Stamina, or hit it). It reports destroyed and decompiles.
3. Use **Recompile** → **no dialog**, and the warning is the destroyed-specific line:

   *"Special Sprite (Minor) was a Special Sprite, and a Special is not rebuilt — it was compiled for one job and that job is over. Compile a new Special Sprite for the new job. Recompile's rebuild is for Data / Attack / Machine / Ward sprites."*
4. It must **not** say *"nothing recently destroyed"*, and it must **not** offer a rebuild.

## 5. Stock rebuild is unchanged

1. **Compile Sprite** → **Data-sprite**. Take it to 0 Stamina; it decompiles.
2. Use **Recompile** → the dialog opens with *"Rebuild Data-sprite (Minor) (just destroyed — reduced power)"* as a target.
3. Confirm → it comes back **where it fell**, at **half Stamina** (rounded up, never below 1), 1 Resonance spent, and the destroyed record is cleared.
4. Use Recompile once more with nothing else out → you are back to §1's plain empty-state line, because the record was consumed.

## 6. What is *not* in this wave

- **Recompile still refuses Specials.** No reshape, no rebuild. Option B was considered and declined.
- **Specials cleanup is still deferred** — token scale, Decompile Specials, removing the standalone Special abilities, Chase Pilot-first seats, VOIDMARK Wire-only. None of it shipped here.
- No pack document, ability, number or journal page moved. If a pack looks rebuilt after pulling this, something else did it.
