# 0.3.136 — Foundry smoke checklist

Thirty-five finished drone plates · Ghostwire-native Mount / Dismount.

**Before you start**

1. Close Foundry, pull `gw-0.3.136`, reopen. The module version in **Manage Modules** should read **0.3.136**.
2. Open the console (F12) on load. There are **no new migrations** in this wave — nothing rewrites your
   world. One new registration line should appear:
   - `draw-steel-ghostwire | Passengers: Mount / Dismount registered (rim seats; weapon hardpoints untouched)`
3. **Turn the third-party Rideable module OFF** before you test item 2. Ghostwire now ships its own
   passenger system and the two will fight over the same token drags.
4. **Art did change this wave** — 35 drone plates were replaced in place. If a drone still looks like a
   silhouette, it is almost always a browser cache: **Ctrl+F5** (or Ctrl+Shift+R) and look again before
   writing it down.

Everything below is in brief order. `✅` when it matches, note what you saw when it does not.

## 1. Drone art — the finished plates are on the table

**What changed.** Michael generated a full 35-drone token pack. Every one of those WebPs has been copied
over the silhouette that was sitting at the same filename, so **nothing had to be re-pointed**: the Items
already pointed at `assets/tokens/drones/<dsid>.webp` and now that file is the finished plate. One rename:
the incoming file was `rustbucket.webp` and the live asset is **`rustbucket-drone.webp`** (the drone's dsid
is `rustbucket-drone`; `rustbucket` is a *vehicle*, the City Runabout, and it keeps its own art).

Two Actors *were* re-pointed: the **Generic Drone (Micro)** and **Generic Drone (Small)** band templates
were still wearing a core Foundry steel-blue robotics icon. They now wear **Fly** and **Guard-Dog**, the
same way **Generic Drone (Medium)** has worn the Mule-Bot plate since 0.3.68.

**What to check.**

1. Open the **Ghostwire Vehicles & Drones** compendium, Drones folder. Scroll it. Every one of the 40
   drones should be a finished illustration — no flat grey silhouettes.
2. Spot-check Michael's four by opening each Item sheet and looking at the art:
   - **Guard-Dog** — Light/Small quadruped
   - **Rustbucket** (the *drone*, not the car) — Light/Small flying clunker
   - **Fly** — Personal/Micro
   - **Sputter-Sled** — Light/Small
3. **Drop each of those four on a scene** (drag the Item onto a hero, then **Deploy** from the Item sheet,
   or use **Deploy & Command**). The placed token must wear the same finished art as the Item, and the
   Actor's portrait in **Actors → Deployed Machines** must match it too. Deploy copies the Item's art onto
   both, so if the Item is right and the token is wrong, say so — that is a real bug.
4. **Sizes are unchanged from 0.3.135.** Nothing in this wave touched scale. Confirm the lock still holds:
   - Personal / Micro band → token art scale **0.5** (Fly, Skitter, Tape-Eye, Buzz…)
   - Light / Small band → **1.0** (Guard-Dog, Rustbucket, Sputter-Sled, Medbot…)
   - Vehicle / Medium band → **1.5** (Mule-Bot, Stinger, Warhound, Hellkite…)

   Check it on a placed token: right-click → **Configure Token** → *Appearance* → **Scale**. A Fly and a
   Warhound side by side should read as obviously different machines.
5. **`rustbucket-drone.webp` is the live filename.** In the Foundry file picker, browse to
   `modules/draw-steel-ghostwire/assets/tokens/drones/`. You should see **`rustbucket-drone.webp`** and
   there should be **no `rustbucket.webp`** in that folder.
6. **Protected plates were not overwritten.** These five were already finished, were *not* in the 35-drone
   pack, and must look exactly the way they did in 0.3.135:
   - **Kiln-Beetle**
   - **Mule-Bot** (both the drone Item and the named Mule-Bot Actor)
   - **Second Face**
   - **Static Crow**
   - **Tide-Wraith**

   `node tools/wave-03136-smoke.mjs` checks these by file hash, so an accidental overwrite goes red
   offline — but eyeball them anyway, they are the five Michael liked.
7. **Generic band templates.** Open **Actors → Summons & Machines → Machines** (or the summons compendium)
   and look at **Drone (Micro)**, **Drone (Small)**, **Drone (Medium)**. Micro should be the Fly plate,
   Small the Guard-Dog plate, Medium the Mule-Bot plate — no steel-blue robotics-frame icon anywhere.

### 1b. Drones already deployed in your world

Most of them fix themselves. Because the art was replaced **at the same filename**, any Actor or token
that was already pointing at `…/drones/guard-dog.webp` is now showing the new plate with no migration at
all — a hard refresh is enough.

The exception is anything stamped from the two band templates that were re-pointed. A **Drone (Micro)** or
**Drone (Small)** Actor that is already sitting in your world still carries the old icon path. There is no
world migrator for this (a fragile one-shot rewrite of Director-owned Actors is not worth it). Fix either
way:

- **Recall** the machine from its gear Item and **Deploy** it again — Deploy re-stamps the art from the
  Item every time; or
- set the art by hand on that one Actor.

## 2. Mount / Dismount — riding a machine

**What this is.** A Ghostwire-native replacement for the third-party Rideable module. Hero tokens can be
put **aboard** a drone or vehicle token; they shrink, sit around the **rim** of the machine, and move with
it. **Dismount** puts them back at their own size in a clear square beside it.

**Naming, so nothing gets confused.** Ghostwire already had a **Mount / Unmount** for *weapon hardpoints*
(bolting a gun to a Turret Ring, 0.3.112). That is untouched and lives on the Machine sheet. This is a
different thing with different buttons, on the **Token HUD** and the **Token toolbar**.

**Capacity (the 0.3.136 default).** No Ghostwire chassis carries a crew-seat number in its data, so the
**band** decides:

| Band | Seats |
| --- | --- |
| Drone — Personal / Micro | **0** (carries nobody) |
| Drone — Light / Small | **1** |
| Drone — Vehicle / Medium | **2** |
| Vehicle — bike | 2 |
| Vehicle — car | 4 |
| Vehicle — air / water / space | 4 |
| Vehicle — heavy | 6 |
| Base asset (bench, door lock, beacon) | 0 |

A Director who wants a different number for one machine sets `flags.draw-steel-ghostwire.machine.seats`
on that machine Actor and it wins over the table.

**What to check.**

1. **Deploy a Medium drone or a car** (Mule-Bot, Stinger, or a Bulldog / Getaway) onto a scene with at
   least two hero tokens.
2. **Put them aboard.** There are two ways in, and they both end up in the same place:
   - **Token toolbar (the reliable one).** Select two heroes (click one, shift-click the other), **target**
     the machine (hover it and press `T`), then press the new **people** button in the left-hand Token
     toolbar — *"Mount — put the selected tokens aboard the targeted machine"*.
   - **Token HUD.** **Target** the heroes you want aboard (hover each, press `T`), then right-click the
     machine to open its HUD and press the **people** icon in the left column — *"Mount the selected
     tokens on this machine (N seats)"*. Targets are used first here on purpose: right-clicking a token
     takes control of it, which drops whatever else you had selected. With nothing targeted it falls back
     to the selection, which works fine when the machine was already the only thing you were holding.

   Either way:
   - Both heroes **shrink to half size** and move onto the **rim** of the machine token — spread around it,
     not stacked on each other.
   - You get a toast: `<names> climbs aboard <machine> (2 of 4 seats).`
3. **Move the machine.** Drag it across the map. Both riders travel with it and stay on their seats.
   **Rotate** it (hold and turn, or set rotation in Configure Token) — the riders swing round with the hull
   and keep their relative seats. Change its **elevation** — they go with it.
4. **A rider cannot walk off on its own.** Try to drag one of the mounted heroes. The drag is **refused**
   and you get `<rider> is riding <machine> and moves with it. Press Dismount to move on foot.`
   This is deliberate: a stray drag in the middle of a fight must not quietly unseat somebody.
5. **Dismount one.** Right-click a mounted hero → the HUD shows a single **walking-figure** button,
   *"Dismount — step off and move on your own again"*. Click it. That hero goes back to **its original
   scale and elevation** and lands in a clear square just outside the machine. The other rider stays put.
6. **Dismount all.** Right-click the machine → the second HUD button, *"Dismount every rider on this
   machine"*. Everybody steps off into their own square. The Token toolbar's **Dismount** button does the
   same job: with riders selected it steps those riders off, and with only the machine selected it empties
   the whole machine.
7. **Capacity refuses.** Deploy a **Micro** drone (Fly, Skitter). Select a hero, press Mount on it — you
   should get `<name> has no room for a passenger. Micro drones carry nobody.` and nothing happens.
   Now deploy a **Small** drone (Guard-Dog), select **two** heroes and press Mount — one gets aboard and
   the other is refused by name: `No seat left for <hero> — <drone> carries 1.`
8. **Already riding.** With a hero aboard, select it plus a second machine and press Mount on the second
   machine. Refused: `<rider> is already riding <machine>. Dismount first.`
9. **Recall / delete frees the crew.** With two riders aboard, **Recall** the machine from its gear Item
   (or just delete the machine token). Both riders are freed where they stand, restored to full scale and
   their own elevation, and you get `<machine> is gone; 2 rider(s) are back on their own feet.`
   They should be draggable normally again straight away.
10. **Initiative is untouched.** Put the machine and both riders in a combat. They each keep their own
    turn — mounting does not merge them, skip them, or reorder the tracker. A rider takes its own turn
    while sitting on the rim; it just cannot move itself with a drag.

### 2b. What must still work (regression)

None of these share code with passengers, but they are the neighbours:

- **Deploy / Recall** a machine from a gear Item — unchanged.
- **Jump-In** (Signature Platform / Deploy & Command → Jump-In) — the pilot goes Jacked In, the meat goes
  inert. Unchanged.
- **Weapon Mount / Unmount** on the Machine sheet — a Category-3 gun still goes onto a Weaponry kit
  hardpoint and still answers to **Gunnery**. Different feature, different buttons, same words. It must be
  exactly as it was.
- **Rigged Fire** from a jumped-in pilot.
